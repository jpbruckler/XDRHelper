# Contributing

Thanks for your interest in contributing to the **XDRHelper Project**.

Whether it's a bug report, new feature, correction, or additional documentation, your feedback and contributions are appreciated.

Please read through this document before submitting any issues or pull requests to ensure all the necessary information is provided to effectively respond to your bug report or contribution.

Please note there is a code of conduct, please follow it in all your interactions with the project.

## Reporting Bugs/Feature Requests

We welcome you to use the Gitea issue tracker to report bugs or suggest features.

When filing an issue, please check [existing open](https://gitea.dtm.dtmidstream.com/Cybersecurity/XDRHelper/issues), or [recently closed](https://gitea.dtm.dtmidstream.com/Cybersecurity/XDRHelper/issues?q=&state=closed) issues to make sure somebody else hasn't already reported the issue. Please try to include as much information as you can. Details like these are incredibly useful:

- The PowerShell version you are using (Windows PowerShell 5.1, PowerShell Core 6.0, etc.)
- The operating system you are using
- A reproducible test case or series of steps
- The version of our code being used
- Any modifications you've made relevant to the bug
- Anything unusual about your environment or deployment
- Any other information you think is relevant

## Contributing via Pull Requests

Contributions via pull requests are much appreciated. Before sending us a pull request, please ensure that:

1. You are working against the latest source on the `main` branch.
2. You check existing open, and recently merged, pull requests to ensure someone else hasn't addressed the problem already.
3. You open an issue to discuss any significant work - we would hate for your time to be wasted.
4. Tests are added or updated to reflect any changes.

## Finding contributions to work on

Looking at the existing issues is a great way to find something to contribute on. As our projects are under continuous development, there's always something to do!
